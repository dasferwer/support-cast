# SupportCast

[![Проверки](https://github.com/dasferwer/support-cast/actions/workflows/ci.yml/badge.svg)](https://github.com/dasferwer/support-cast/actions/workflows/ci.yml)

Сервис прогнозирует число обращений на ближайшие семь дней и пересчитывает прогноз после загрузки новых данных. Можно исправить историю, проверить, на какой её версии построен результат, и оценить число операторов по дневной нагрузке.

Главная инженерная задача — сохранить связь между принятыми данными и фоновым расчётом. Загрузка, версия ряда и задание записываются одной транзакцией. Worker переживает остановку процесса; запоздалый результат старого исполнителя не заменит актуальный.

## Запуск

Нужны Docker Compose; для разработки и обучения — Python 3.12 и uv.

```bash
docker compose up --build -d --wait --wait-timeout 180
make test
make smoke
```

Swagger: <http://localhost:8170/docs>. Вход через `/auth/login`: `demo@example.com` / `SupportCastDemo123!`. Локальные демонстрационные данные создаются автоматически. Первый прогноз обычно появляется через несколько секунд.

```bash
uv sync --extra dev --frozen
make check
make recovery
```

`make recovery` временно завершает worker этого проекта через SIGKILL и проверяет продолжение того же задания. Данные PostgreSQL остаются в volume. `docker compose down` останавливает проект без удаления истории.

## Что можно проверить

- Создать свой ряд через `POST /series`, загрузить дневные значения через `PUT /series/{id}/observations` и получить семь точек прогноза.
- Повторить загрузку с тем же `Idempotency-Key`: вернётся исходное задание. Другие данные с тем же ключом дадут 409.
- Исправить историю с её текущим `ETag` в `If-Match`. Старый прогноз получит `stale: true`, новый посчитается автоматически.
- Передать пропущенный день как `null`; увидеть в результате число пропусков и необычных значений. Нули остаются настоящими нулями.
- Сравнить Ridge и «тот же день прошлой недели» на восьми последовательных тестовых неделях.

## Модель и границы результата

В демонстрации используются открытые дневные обращения NYC 311 **по последствиям урагана Sandy**, опубликованные FiveThirtyEight. Это узкий исторический набор, а не типичная нагрузка коммерческой поддержки. Его происхождение, лицензия и ограничения описаны в [карточке модели](docs/model-card.md).

На тестовом отрезке 06.11–31.12.2014 MAE составила **1,078** обращения у Ridge против **1,589** у недельного повтора. WAPE модели — **73,65%**: малые абсолютные ошибки здесь не означают высокую точность планирования. Разреженный отрезок 2017 года также сохранён в отчёте. Перенос качества на другую службу поддержки не проверялся.

Оценка операторов делит дневной объём работы на продуктивное время человека. Она не рассчитывает очередь, SLA, смены или время ожидания.

## Независимая проверка качества

Два лицензированных UCI Bike Sharing ряда, временная калибровка до test и четыре режима (исходный, пропуски, новый уровень, выбросы): [протокол, результаты и ограничения](docs/independent-evaluation.md). MAE/WAPE и coverage по каждому из семи горизонтов сохранены в JSON. Прямой перенос Sandy-интервалов даёт почти нулевое покрытие; отдельная калибровка улучшает его, но не гарантирует номинальные 90% при смене уровня. Production artifact не изменён.
